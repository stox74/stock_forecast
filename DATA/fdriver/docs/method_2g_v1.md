# fdriver 2g 방법 v1 (method_2g_v1)

- 작성: 2026-10-19. 2g 의 어떤 예측·비교 결과도 계산하기 전에 쓴다.
- 이 문서는 git 커밋으로 시점을 남긴다. 고치면 '변경 기록'에 날짜와 이유를 적는다.
- 2g 는 판정 가설이 없다.
  - 이 문서는 대안 예측(OP_hat_alt) 비교와 표시 열의 정의를 결과보다 먼저 고정하려는 것이다.
  - 2g 기록은 사전 등록(2d v2) 가설의 표본이 아니다.
- 2d 의 코드·규칙·기록(fd_rev_adj_2d, fd_op_rule, fd_live_2d, 사전 등록 v2)은 바꾸지 않는다.
- 아래 '2g 전용' 수정은 2g 표에만 적용한다.

## 1. 대상

- 출발점: 2d K1 조사표 `2d/K1/k1_universe.csv` (K1 실행 시점 상장 보통주 2,691곳)
- 대상 = (A) ∪ (B)
  - (A) coverage_class '정상' 이고 2d 필터 1~5 를 모두 통과한 기업 (`pass_all_ex39`)
  - (B) 기존 레이더 39곳 (`in_radar39`)
    - 레이더 39곳은 지시문에서 이름으로 정한 집단이라 필터를 통과하지 못해도 넣는다.
    - 통과하지 못한 필터는 `filter_fail` 열에 적는다.
- 2d 확대 73곳(fd_driver_map_2d driver·ts_only)은 뺀다.
- 2d 필터 (K1 정의 그대로)
  1. 매출 이력: 32분기 이상 + 2019Q1~2023Q4 20분기
  2. 최근 4분기(2025Q3~2026Q2) 매출 합 300억 원 이상
  3. 주가 이벤트 12건 이상
  4. 기업 사건: 표시만 함
  5. 금융·지주 제외
- 매출 음수 분기 기업 제외: K1 점검표(`k1_revenue_basis_check.csv`, negative_revenue) 기준
- 매출 기준 보정
  - 2d K2 `adjust()` 와 같은 규칙: DG 우선, 같은 기준일 때만 DART 로 채움, DART 기준 기업은 누적 차분, 원인 진단, flag_basis
  - 기간만 2009Q1 ~ 실행 시점에 끝난 마지막 분기로 늘린다.
  - 저장: `fd_rev_adj_2g` (upsert 작업 표)
- 보정 매출로 선정 구간 20분기가 다 차지 않거나 보정 뒤에도 음수 분기가 남은 기업은 뺀다.
  - 레이더 39곳도 이 조건은 적용한다. 예측을 계산할 수 없기 때문이다.
- flag_jump = K1 rev_jump_q >= 4 (2d 와 같음)
- 단계별 기업 수를 보고한다.

## 2. 영업이익 자료와 규칙

- 항목(영업이익·매출원가·판관비)은 2d `k3_oprule.items` 와 같은 원천 규칙을 쓴다 (DG 기준이면 DG, 빈 분기 DART / DART 기준이면 V3 → V2).
- **2g 전용: DART 판관비 항등식 수정 (sga_fixed)**
  - 대상: 매출 기준이 DART 인 기업의 모든 분기
  - 잔차 = 매출(fd_rev_adj_2g) - 매출원가 - 영업이익
  - 판관비가 있고 매출원가·영업이익·매출이 모두 있을 때, |판관비 - 잔차| > 0.02 x |잔차| 이면 판관비를 잔차로 바꾸고 sga_fixed = 1
  - 판관비가 없고 잔차를 계산할 수 있으면 잔차로 채우고 sga_fixed = 2
  - 고친 기업 수·분기 수를 보고한다.
  - DG 기준 기업(DG 판관비 = 매출총이익 - 영업이익)은 고치지 않는다.
- **규칙 배정**: 2d K3 와 같은 방법·기준값, 선정 구간 2019Q1~2023Q4 (R4 → R1 → R2 → R3)
  - R4: 자료 부족 n_q < 12, 매출 50억 미만 분기 4개 이상, 또는 c 표준편차 > 0.15
  - R1: HAC(4) b > 0, p < 0.05, R^2 >= 0.3
  - R2: 매출원가·판관비 20분기
  - R3: 그 외
- **표시**: K4b 기준
  - flag_spread: KSIC 19, 201, 203, 205, 241, 242
  - flag_q4: 4분기 판관비 > 그해 평균 x 1.5, 또는 4분기 영업비용률이 1~3분기 평균보다 10%p 이상 높은 해가 2개 이상
- 저장: `fd_op_rule_2g`

## 3. 매출·영업이익 추정

- 기준일 t 의 스냅샷마다 두 분기를 예측한다.
  - Q = t 기준 마지막으로 끝난 분기 (2026-10 이면 2026Q3)
  - Q+1 (2026Q4)
- t 에 아는 분기는 2d 와 같다: 첫 공시일 <= t, 없으면 법정 기한.

### 3.1 매출

- 2d `k4_forecast.run_entity(method_v2=True, live_t=t)` 를 그대로 쓴다. 입력만 2g 표(fd_rev_adj_2g, 2g 항목, fd_op_rule_2g)다.
- 개별 예측: SARIMA (후보 8개 AICc 최소), ETS (감쇠 추세 + 계절 4), Theta (계절 조정 후 가법), B2 (최근 아는 분기 g)
  - 2d v1 의 TS·E 도 같이 남긴다.
- M1: 기존 레이더 39곳 중 드라이버가 있는 기업만, Q 에만 쓴다.
  - 값: 같은 기준일 t 의 레이더 build (`radar.build.build(Q, t)`) 의 g_M1 (주 드라이버 모형)
  - Q+1 은 드라이버 달이 하나도 공표 전이라 M1 을 쓰지 않는다.
  - 시범 대조군 2곳(006040, 003350)은 드라이버가 없다.
- **E5** = 있는 개별 예측 g 의 평균 (= 매출 기하평균)
  - M1 이 있으면 SARIMA·ETS·Theta·M1·B2, 없으면 SARIMA·ETS·Theta·B2
  - 빠진 모형은 빼고 평균하며, e5_n 에 모형 수를 적는다.
- 표시 열 (판단 참고용, 예측식은 바꾸지 않음)
  - `flag_b2_jump` = |g_B2 - median(g_SARIMA, g_ETS, g_Theta)| > 0.20 (로그 성장률 차이, 20%p)
  - `flag_m1_dir` = M1 이 있고, sign(g_M1) 이 g_SARIMA·g_ETS·g_Theta·g_B2 네 개 모두와 반대 (각각 곱이 음수). M1 없으면 결측.

### 3.2 영업이익

- **OP_hat_E5** (주 예측): fd_op_rule_2g 규칙에 매출 E5 를 넣은 값 (2d 와 같은 계산)
  - R1: a + b x E5. a, b 는 2019Q1 ~ t 까지 아는 분기 OLS.
  - R2: E5 x (1 - 원가율_hat) - 판관비_hat. 비용 계열 예측이 안 되면 R3 로 대체 (K4b).
  - R3: E5 x (1 - c_hat)
  - R4: 예측 안 함
- **OP_naive** = B2 매출 x 전년 동기 영업이익률 (t 에 아는 값)
- **OP_hat_alt** (2g 전용 대안, 매출 입력 E5)
  - R1 기업: a, b 를 t 이전에 아는 최근 12분기만으로 OLS. 12분기가 안 되면 결측.
  - R2 기업: 판관비 계열을 먼저 바꾼다.
    - 각 분기 s 에서, 바로 앞 4개 분기(원래 값) 중앙값의 1.5배를 넘으면 그 중앙값으로 바꾼다.
    - 앞 4개 분기가 다 있어야 하고, 아니면 그대로 둔다.
    - 그 뒤 주 예측과 같은 SARIMA(1,0,0)(0,1,1)4+상수·ETS·Theta 로 판관비를 예측한다. 원가율 예측은 주 예측 값을 쓴다.
    - 주 예측이 R3 로 대체된 기업은 주 예측과 같게 둔다.
  - R3 기업: 주 예측과 같음
  - R4: 예측 안 함
- **flag_op_sign**: OP_hat_E5, OP_hat_alt, OP_naive 중 값이 있는 것이 2개 이상이고, 그 부호가 서로 다르면 1

### 3.3 컨센서스 비교

- cons = t 이하 관측일 중 최신 매출 컨센서스 (`adapters.kr_consensus.read_consensus`, monthly)
- cons_asof = 그 관측일
- gap_E5_vs_cons = ln(E5 / cons)
